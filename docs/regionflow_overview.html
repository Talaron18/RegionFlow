RegionFlow

An attempt to edit one specific object in a photo, such as “make this can blue”, without touching the rest of the picture and without also changing the other cans that look just like it.

Finding the region: works Clean edits from our own model: not yet Few-step sampling: works, with a scale rule Instance-selectivity benchmark: built and scored

1. What the project is

Image editors driven by text (“turn the apple red”) are now common. They tend to fail in a specific way when a picture contains several things of the same kind. Ask to recolour one apple in a bowl of apples and many editors recolour every apple, or the wrong one, or smear the whole bowl. The project calls this instance leakage.

RegionFlow’s goal, unchanged from the first day, is an editor that does five things at once:

  1. changes the named attribute (usually colour) of the named object,
  2. keeps that object’s identity, shape and texture,
  3. leaves everything outside the object untouched,
  4. leaves no visible seam at the boundary,
  5. does not affect other instances of the same category. This last requirement is the research problem; the other four are infrastructure.

It is built on Stable Diffusion 3 Medium (SD3-Medium), a 2-billion-parameter open image generator. The compute budget is one consumer GPU (an RTX 3090 Ti with 24 GB) plus occasional six-hour blocks on 8×A100. That rules out out-training large labs, so the contribution has to be a mechanism or a measurement.

The work is organised as gates: separate experiments that each test one claim and are judged against a pass/fail threshold written down before the run.

Gate A: the edit mechanism

Can a small trained add-on turn a source image into the edited image by a learned move in latent space?

Negative so far

Gate B: speed

Can SD3, which normally needs ~50 steps, be adapted to produce images in 1–4 steps?

Passed, with a stated correction

Gate C: the measurement

Build a benchmark where some same-category objects are meant to stay unedited, then score existing editors on it.

2. Background in five minutes

You need five ideas to follow the rest of this page.

Latents

SD3 never works on pixels directly. A VAE (variational autoencoder) compresses a 512×512 RGB image into a latent: a 16-channel grid of 64×64 numbers, eight times smaller per side. Editing happens on that grid; the VAE decodes the result back to pixels at the end.

Flow matching and velocity

SD3 is a rectified-flow model. Picture a straight line from pure noise (t = 1) to a real image latent (t = 0). The network is trained to predict, at any point on that line, the velocity: the direction to move to get closer to the image. Generating means starting from noise and taking many small steps along the predicted velocity, usually about 50. Running those steps backwards, from an image to noise, is called inversion.

The transformer (MMDiT)

The network that predicts velocity is a Multimodal Diffusion Transformer with 24 blocks. It cuts the 64×64 latent into 2×2 patches, which gives 1,024 image tokens. It also takes 333 text tokens from three text encoders (two CLIP models and T5-XXL), plus a 2,048-number summary vector of the prompt called pooled_projections. Image and text tokens attend to each other jointly in every block. The pooled vector and the timestep steer each block through scale-and-shift modulation (adaLN).

LoRA

Instead of retraining all 2 billion weights, LoRA freezes them and adds a small trainable correction to selected layers: a pair of thin matrices whose product is added to the layer’s output. “Rank 16” means the matrices are 16 wide. RegionFlow’s add-ons start at exactly zero, so before training the wrapped model is bit-for-bit the original SD3.

Masks and instances

A mask is a black-and-white image marking the region to edit. An instance is one individual object; a category is the kind (“can”, “giraffe”). Same-category instances that should stay unedited are called siblings.

3. The journey, in order

Each step below was triggered by the result of the one before it.

Stage 0: steer SD3 without training

negative

Invert the photo to noise, then regenerate it while biasing attention inside the mask and pinning everything outside. Localisation was excellent. But every setting that changed the colour also destroyed the object’s structure in equal measure.

Gate A, first run: learn the edit as a move

negative

Train a LoRA to predict the displacement from source latent to target latent and apply it in one step. Output went from “no visible change” straight to blur. The metric used to judge it was also found to be broken: the ground-truth edits scored worse than the model.

Gate B: make SD3 fast (MeanFlow)

positive with a rule

First run: the adapter was worse than doing nothing. After the regression target was fixed, it beat the frozen model at every tested interval, given one inference-time scale constant.

Gate C: build the benchmark and score other people’s editors

positive

151 hard cases with sibling masks. Handing an editor the right mask drops wrong-instance edits from 40% to 0%. Edit quality does not improve: four in five outputs are still not clean.

Gate A reopened: why does our edit blur?

negative, well-diagnosed

Tested the “many possible edits average into mush” theory with a noise-injection sweep (Direction A) and six cheap diagnostics. Ambiguity was ruled out as the main cause; the mask path works. What remains is how precisely the one-step readout can place the edit.

Current: sharpen with a perceptual loss

built, not yet trained

LPIPS loss did not sharpen outputs. A pre-check found DINOv2 features separate blurry predictions from sharp targets about 8× better (30.1 vs 3.8), so a DINOv2 patch loss was added. A synthetic red→blue circle test shows the current model still fails an unambiguous edit.

4. Stage 0: editing with two hand-built fields

In plain words: turn the photo back into noise, then regenerate it, while telling SD3 “inside this region, listen to the word blue” and “outside it, copy the original”.

Stage 0 needed no training. It added two spatial maps (“fields”), both built from one mask:

λ: the attention bias field

Adds a bonus (+4.0) to attention between image tokens inside the mask and the edit words in the prompt, and a penalty (−2.0) outside. A graded band of width r around the edge was meant to prevent seams.

region/lambda_field.py · region/sd3_processor.py

τ: the inversion-depth field

Pins tokens to the original image’s inversion path for most of the generation. Background tokens stay pinned almost to the end; target tokens are released early so they can change.

region/alpha_field.py · bench/inversion.py

What it found

A 3×3 grid of settings on three real photos (a ball, a sheep, a phone booth) gave one clear result. The more the colour moved (ΔE), the more the object’s structure was destroyed. The correlation between the two was −0.958, −0.726 and −0.955. The sheep’s weaker number has a simple cause: it was white, so there was little chroma to lose.

Headline negative (F1)

Edit strength and source destruction lie on the same axis. A mixing ratio between “original” and “freshly generated” can only say how much to keep, never which direction to move. Colour is decided early in generation, when content is still noise-like, so releasing a region early enough to change its colour also releases its shape.

Headline positive (F2)

Localisation is solved. Background change stayed at 0.012–0.026 everywhere, seams were near zero, and SAM masks matched ground truth at IoU 0.82–0.86. Finding where to edit was never the problem; what to turn it into was.

Two smaller findings: the band radius r did nothing useful (selectivity flat at 0.93–0.95 for r ∈ {0,1,2,4}), and inversion error on real photos is structural (geometry gets rearranged) rather than random noise. This motivated Stage 1: replace the mixing ratio with a learned direction.

5. The current model: a transport adapter on SD3

In plain words: keep SD3 frozen, bolt on about 11 million trainable numbers, and teach the combination to look at the source image, the mask and the instruction and output “how far, and in which direction, each latent value should move”. Add that move to the source and decode.

Three design guarantees

  • Identity at start. Every new output layer starts at zero, so before training the model equals SD3 exactly. Any change measured later comes from training, not from the wrapper.
  • A gate on every new path. Each add-on is multiplied by a per-sample gate. In the edit (“pair”) mode the gate is always 1, so the add-ons stay active at s = 0, the only point where the edit is read out. In the few-step (“meanflow”) mode the gate encodes the interval instead.
  • Mask enters the latent, not the attention. Stage 0 showed attention bias ties “how loudly the instruction is heard” to “how much of the original is destroyed”. Here the mask instead says where a learned move applies.

Mask encoder variants

Two versions exist, chosen with --mask-encoder-kind:

single (default)

One CNN head produces the whole shift. It learned a large, near-constant offset across the whole image plus a small mask-shaped part.

global_local

The shift is forced to split into a learned constant vector (the “operating point”) plus a local CNN output with its average subtracted. The local part cannot drift into the constant, whatever it learns.

6. How it is trained

Training data

  • Dataset: MagicBrush, a human-annotated instruction-editing dataset. Each item is a source image, an instruction, a target image and a mask of the edited area.
  • Only first turns. MagicBrush sessions are multi-turn; later turns start from a model output rather than a real photo, so only turn_index == 1 is used. That gives 4,511 triplets.
  • Mask convention: the mask is the alpha channel, with alpha < 128 meaning “edit here”. Reading the RGB channels by mistake once produced a confident wrong claim.
  • Pre-encoded cache: images are resized to 512×512 and encoded once (VAE mode, not a random sample), the mask is pooled to the 64×64 latent grid, and text embeddings are deduplicated by instruction. Training reads only this cache.

What the model is taught: the straight-line “pair flow”

Draw a straight line in latent space from the source to the target. The velocity along it is constant and equals the whole edit. Training picks a random point on the line and asks the model to predict that velocity.

z_s = (1 − s) · z_src + s · z_tgt s ~ Uniform(0, 1) v = z_tgt − z_src (the true edit, constant along the line) u = model(z_s, s, r, text, mask) loss = mean_inside_mask (u − v)² + mean_outside_mask (u − v)² edit = z_src + u(z_src, s = 0) · M (read out in ONE step)

Outside the mask the target equals the source, so v = 0 there and that term teaches the model to leave the background alone. The two halves of the loss are reported separately, so a model that wins by moving everything a little is visible.

7. What the current model can do today

Short answer: it knows where to edit and roughly which way to push the colour, but it cannot yet produce a clean, sharp edit. It has never been scored on the Gate C benchmark.

The clearest single test

A synthetic image with a red circle and a green circle, the instruction “change the red circle to blue”, and a mask on the red circle only. Nothing about it is ambiguous. The four panels are the source, the target, the oracle (the true latent difference pasted in, to check the VAE and the masking), and the model’s output from the best checkpoint (σ0 = 0).

Accuracy against the true edit

The main measurement is the cosine between the model’s predicted move u and the true move v, over all 4,511 cached examples. 1.0 would be perfect, 0 is unrelated. It is scored three ways, because “where” and “which way” fail differently:

  • raw: the whole frame, pixel by pixel. Needs both the right direction and the right location.
  • pooled: averaged over the mask into one value per channel. Only asks “right direction?”.
  • centered: pooled, minus the average shift every MagicBrush edit shares. Asks “right direction for this instruction?”.

How to read this:

  • The model beats the instruction-only ceiling on every treatment, so it really does use the source image, not just the words.
  • Removing the mask more than halves raw (0.541 → 0.240): the mask is doing real work, mostly for where.
  • The gap between raw (0.541) and pooled (0.769) is position error: right average direction, wrong exact pixels. That gap is the main open problem.
  • A cosine of ~0.54 in latent space does not translate into a clean picture, as the synthetic test shows. These numbers measure progress on a proxy, not edit quality.
Not yet measured

The Gate A model has never been run through the 151-case Gate C benchmark or the calibrated quality judge. The wrapper to do so exists (bench/gate_a_model.py); it needs a GPU run.

8. Diagnosing why the edit blurs

The first explanation was mean collapse. If “make the dog brown” could mean many different browns, a model trained with squared error learns their average, which looks like a desaturated smear. The reopened Gate A tested that and five other explanations cheaply, without retraining:

What is left standing: a single forward pass at s = 0 cannot place the edit as precisely as the mask allows. The synthetic test adds one more observation: on an unambiguous edit, the output is muddy and gridded rather than blue.

A plausible root cause (reviewer’s reading, not yet tested)

SD3 was trained to turn noise into images. Gate A instead queries it at a clean image and asks a small add-on to emit a displacement. Nothing keeps z_src + u on the set of latents that decode to natural images, and the noise-driven sampling that makes ordinary editors sharp is missing by design. The test that would settle this is a noise-start, mask-conditioned control trained on the same data.

9. Gate B: making SD3 fast

In plain words: instead of predicting the direction to move right now and taking 50 tiny steps, predict the average direction over a long stretch so a few big steps land in the same place.

This is MeanFlow. The model gets a start time t and an end time r and predicts the average velocity over [r, t]. The same adapter structure is used in "meanflow" mode: rank-32 gated LoRA, learning rate 5e-5, with 75% of each batch at r = t (“anchors”), where the target reduces to ordinary flow matching. It was trained on the same MagicBrush latents and scored against a ground-truth average velocity integrated from the frozen model.

  • Stage 1: the adapter was worse than simply reusing SD3’s instantaneous velocity at every interval. Its correction pointed nowhere (cosine to the needed correction ≈ 0).
  • Stage 1B: the cause was the regression target, not adapter size. With the target fixed, cosine rose to ≈ 0.72.
  • Stage 1C: a “distill” variant reached cosine 0.70–0.78 across intervals. It beats the frozen model at every tested time (0.20–0.80) and interval (0.1–0.5) given one rule: scale the correction by 1.0 below t = 0.35 and by 0.5 above.
  • Δ-curriculum: training short intervals before long ones adds about 3%, reproducibly across two seeds.
Caveat

The scale rule fixes magnitude, not direction. The leftover direction error (1 − cos², 0.26–0.67 depending on time; 0.44 at the Δ = 0.5 operating point) is now the binding limit. Gate B is also a generation speed-up; it has never been connected to the editor. The project’s own plan says few-step should come last.

10. Gate C: the instance-selectivity benchmark

In plain words: collect photos with several objects of the same kind where only one should change. Then check whether editors change the right one, leave the others alone, and do a good job.

How it was built

  • Cases: 151 “hard” cases from RefEdit-Bench joined to COCO, which annotates every instance of 80 object categories, so sibling masks are available. Example instruction: “Remove the giraffe right next to the lady”.
  • Where: change inside the target mask versus change on siblings and on the background. A case is mis-targeted when the siblings changed more than the target. This classifier agreed with human judgment on 14/14 checked cases.
  • Off-instance: a peak detector for edits that land on an untracked object (for example, a parrot placed on the stove instead of the chef’s shoulder).
  • How good: a 40-case blind human audit (clean / degraded / destroyed / wrong edit / no edit), plus a VLM judge using the VIEScore protocol. The judge (GLM-5.3-Flash) correlates with the human verdicts at ρ = 0.717.
  • Frozen rules: every threshold was fixed before any model was scored.

The defensible claim

Conditioning on the target instance’s mask eliminates wrong-instance editing (28% → 0%, or 40% → 0% within one model family) and buys no measurable improvement in edit quality (15% → 22% clean, p = 0.51). Four in five outputs remain unclean. The mask decides where the model edits, not what it does there. No other benchmark leaves same-category instances deliberately unedited, so this ceiling of “route the edit to the right place” methods had not been measured before.

11. What has been learned

Localisation is solved; transformation is not

Found in Stage 0 and again, independently, in Gate C. Masks fix where. Nobody’s mechanism, including this project’s, yet reliably fixes what.

Mixing ratios cannot express a direction

Blending original and regenerated content couples colour change to structure loss (correlation ≈ −0.95).

Ambiguity is not why Gate A blurs

Six cheap checks ruled it out. The open suspect is the one-step readout and how it places the edit.

Few-step conversion works at LoRA rank

With the right target and one scale rule. Direction error remains the limit.

Score the ground truth on your metric first

The Stage 0 structure metric rated real human edits worse than the model, which proved the metric measured something else (luminance edges).

Automated verdicts need eyes

Every automated verdict in the project was wrong at least once, which is why the eval tool refuses to print one until --i-looked-at-the-images is passed.

Claims that were made and later withdrawn

“Stage 0 decouples colour from structure.” Withdrawn: the metric was an artifact.

“SD3’s flow field is too stiff for few steps (S ≈ 15).” Withdrawn: the number came from CFG amplification and an aliased timestep embedding. Real trajectory curvature is ~2.84, implying a floor near 3 steps.

“Changing the target raised cosine to 0.72 with the same LoRA.” Do not quote: that was Gate B’s generation task, not Gate A’s edit.

“Mean collapse from ambiguity explains Gate A.” Superseded by the elimination sequence in §8.

“The band radius r helps.” Withdrawn: flat across r ∈ {0,1,2,4}.

12. Open problems and next steps

In priority order. All of them need a GPU and the data cache, which the cloud review environment does not have.

  1. Score the existing best checkpoints on Gate C (σ0 = 0 single and global_local), using the calibrated judge and the blind-audit rubric. Without this, nothing else has a baseline to beat.
  2. Run the DINOv2-loss experiment with a kill criterion written first. Pass means a recognisably blue circle in the synthetic test and a better clean rate than a no-DINO control trained with the same flags. Fail means stop the displacement-regression line.
  3. Run the control the thesis avoided: a noise-start, source-and-mask-conditioned flow-matching fine-tune at full steps on the same data. If it wins, the “no noise” premise was the bottleneck.
  4. Publish Gate C on its own. The benchmark and the “routing saturates, quality doesn’t move” result stand whatever happens to the editor.
  5. Check one open risk: older checkpoints were trained with r = s but are queried with r = 1. Compare the two on the σ0 = 0 checkpoint.
Code state to know about

Commit 9c67baa changed the training objective: interval conditioning became the default, and in that mode σ0 was silently ignored. The review branch now rejects interval conditioning with σ0 > 0, restores the self-test, fixes a crash in the DINOv2 loss for erode = 0, and adds --interval-conditioning / --no-interval-conditioning and --perceptual-mask-erode flags. Neither current setting reproduces the r = s objective of the documented checkpoints, so new runs need a matching control.

13. Glossary

Latent (z)
The compressed 16×64×64 version of a 512×512 image that SD3 works in.
z_src, z_tgt
Latents of the source (before) and target (after) images.
Velocity (v, u)
The direction to move a latent. v is the true one; u is the model’s prediction.
Rectified flow
Training a model to move along straight lines between noise and data, or here between source and target.
Inversion
Running generation backwards to find the noise that would regenerate a given photo.
MMDiT
SD3’s transformer, where image and text tokens attend to each other in every block.
LoRA
A small trainable low-rank correction added to frozen layers.
Gate
A self-contained experiment with a threshold fixed before running it.
Oracle mask
The true mask of the target instance, given to the model rather than predicted.
Mis-targeted
A case where same-category siblings changed more than the requested target.
Cosine (raw / pooled / centered)
Agreement between predicted and true edit direction; see §7 for the three treatments.
σ0 (Direction A)
Strength of noise injected inside the mask during training, meant to choose between several possible edits.
MeanFlow
Predicting the average velocity over an interval so a few big steps replace many small ones.
LPIPS / DINOv2
Neural feature spaces used to compare images by appearance rather than by raw pixels.
VIEScore
A published protocol for asking a vision-language model to grade edits on instruction-following and image quality.
